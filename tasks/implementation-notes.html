Design Decisions

Daily Workout Card is treated as a one-way personal training card because it was created after the health automation cancellation and does not collect health data.

Nightly Validation Controller: The controller will separate queue admission (run) from promotion consumption (consume). Consume mode will produce a deterministic local Mission Control payload and receipt only; actual Mission Control writes remain outside this scoped build.

Nightly Validation Controller verifier repair: The lifecycle is now three explicit phases: admit creates a bounded admission artifact without consuming hashes; reconcile requires complete full-schema validation results and emits at most one promotion; consume revalidates the integrity-checked promotion and POSTs the full camelCase payload to the Mission Control deduplicating endpoint.

Canonical artifact names: Admission is always admission.json inside a unique timestamped run directory. Reconciliation preserves history by writing a timestamped promotions-HHMMSSffffff.json envelope beside it; consumers must use the returned promotion path.

Mission Control: Additive task metadata uses the existing Convex task record rather than a second task store. dedupeKey has a dedicated index and upsert mutation. The full admission contract applies only when sourceSystem is nightly-validation-controller, so legacy task callers remain compatible.

Fresh-review hardening: The controller and Mission Control now share one camelCase admission contract. Stored verifier fields include verdict, confirmation, verification time, candidate/source linkage, evidence and distribution scores, and fatal-constraint state. The Convex upsert uses the same extracted create/update resolver covered by tests.

Mission Control: The existing /overnight route is reused as the Nightly Validation surface. It reads only local controller queue, state, decision, and promotion files. It has no write controls and does not add a top-level navigation lane.

Deviations

Nightly Validation Controller: Consume mode writes a local deterministic payload receipt instead of calling Mission Control. This is an intentional staging boundary because this implementation task explicitly excludes Mission Control application code and external systems. The approved cron was not created or edited.

Superseded implementation note: Consume mode now calls Mission Control in non-dry-run mode because the follow-up contract explicitly requires POST upsert. Verification used an ephemeral local HTTP server and a closed local port; no live Mission Control task was created. Cron installation remains excluded.

Mission Control: No Today ranking or score logic changed. Workstream views are projections over additive metadata and existing status/waiting fields, not a replacement status model.

Fresh-review hardening: Added Now and Paid Delivery projections to Work. Overnight Validation remains only on the separate read-only route and is not duplicated as a Work filter.

Tradeoffs

Implementation is phased to prevent simultaneous cron, Mission Control, and state-contract changes from obscuring root causes.

Nightly Validation Controller: Standard-library Python and explicit JSON/JSONL contracts are favored over framework dependencies. Source freshness is checked against an evidence timestamp, while verifier freshness is checked independently at promotion time.

Integrity boundary: Evidence must resolve beneath approved workspace roots and match its declared SHA-256. Admission and promotion envelopes also carry canonical hashes so edits after gating fail at consume time. This is deterministic tamper detection, not secret-key authentication.

Mission Control: Nightly admission is enforced twice, at the HTTP boundary and inside Convex. The minimum score is 30 of 40. Lower-scoring records and incomplete promotion payloads cannot enter Convex through the nightly source identity.

Fresh-review hardening: Nightly admission also requires promote verdict, confirmed verifier, verification within 24 hours, candidate/source linkage, evidence score at least 4, distribution score at least 3, and no fatal constraint. Legacy source, dedupe_key, and snake_case aliases are rejected before normalization can discard them.
