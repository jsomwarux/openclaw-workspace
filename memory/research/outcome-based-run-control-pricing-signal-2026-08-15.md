## Signals
- Enterprise AI-agent pricing language is moving toward outcomes, but the buyer-safe version keeps a measurable success event in the foreground. Search results framed outcome pricing as paying only when the agent succeeds, when a ticket resolves, or when an audit completes.
- Marketplace and platform coverage adds an important caveat: outcome-based fees only make sense when the result can be clearly measured and attributed. That caveat supports packaging around a narrow workflow ledger rather than broad "agent labor" claims.
- Governance coverage keeps audit trails, scoped permissions, metering, revocation, access control, and compliance evidence attached to production agent use. This is not separate from pricing; it is the proof layer that lets buyers trust the outcome metric.

## JT Relevance
- For the live `Strategy: Package Outcome-Based Run Control` item, the clean buyer frame is: "pay for verified workflow outcomes, not generic automation." The artifact should show source record, allowed action, reviewer/approval state, evidence link, exception path, and final measured outcome.
- Keep the package narrow enough that attribution is defensible: resolved ticket, completed audit, approved owner action, cleared exception, or documented hold. Avoid pricing language tied to vague productivity or autonomous-agent activity.
- Useful proof language: "outcome priced only where the control record proves what changed, who approved it, and which event counted."
